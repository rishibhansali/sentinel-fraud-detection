# CI implementation plan

**Goal:** Make fresh-runner PR and main-branch verification match Sentinel's documented local checks.

**Spec:** `docs/superpowers/specs/2026-10-07-ci-design.md`

## Task 1: Workflow

**File:** `.github/workflows/ci.yml`

- [ ] Trigger on every pull request and push to `main` with `contents: read` only.
- [ ] Add a backend Ubuntu job with Postgres 16 and Redis 7 health-checked service containers, ports 5432 and 6379, and the local test DSN/Redis URL.
- [ ] Set up Python 3.12, create `backend/.venv`, and install `backend/requirements.txt` into it.
- [ ] Loop over `infra/migrations/*.sql` in filename order, passing each file to `psql` inside the Postgres service container with `ON_ERROR_STOP=1`.
- [ ] Run `cd backend && .venv/bin/python -m pytest`, then `backend/.venv/bin/python scripts/smoke_phase5.py` sequentially.
- [ ] Add an independent frontend Ubuntu job: Node 22, `cd frontend && npm ci`, `npm test`, `npm run build`.

## Task 2: Documentation and verification

**File:** `README.md`

- [ ] Document when CI runs, what its two jobs check, and that it needs no repository secrets.
- [ ] Check the workflow against GitHub's syntax and the project environment instructions.
- [ ] Run backend pytest, frontend tests/build, and real smoke locally; push a PR and inspect both GitHub Actions jobs until completion.
- [ ] Merge the PR, repeat the full suite and build from main, and remove the feature worktree and branch.

## Review focus

- [ ] A fresh database receives all eight migrations in order, including `CREATE INDEX CONCURRENTLY` outside a transaction.
- [ ] The workflow never assumes `psql` exists on the host runner or installs it globally.
- [ ] Backend suite and smoke do not run concurrently against one database.
- [ ] Pull requests from forks need no secrets or write token.
- [ ] A job failure produces a failing PR check rather than being swallowed by a shell loop.
