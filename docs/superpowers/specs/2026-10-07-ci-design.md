# CI for Sentinel

## Outcome

Every pull request and push to `main` runs the same backend suite and frontend checks used for local completion. A fresh PostgreSQL 16 and Redis 7 service accompany the backend job; migrations 001–008 are applied in filename order before tests. CI also runs the real Phase 5 API/pipeline smoke script, which cleans up its reserved rows and rule edits. The frontend job runs `npm ci`, all Node tests, and the production Vite build independently.

## Boundaries

This change adds verification only. It does not deploy the app, require credentials, replace the local Docker workflow, install dependencies system-wide, or add authentication. It grants the workflow only repository read permission. The test database password is the existing development-only value used in local Docker Compose, never a production secret.

## Runner contract

Use an Ubuntu 24.04 runner for each job. Install Python 3.12 through `actions/setup-python`, then create `backend/.venv` and install pinned backend requirements there. PostgreSQL and Redis are GitHub Actions service containers with health checks and localhost port mappings. Apply SQL files through `psql` already present inside the Postgres container, including the concurrent index migration and `psql` directives. Run backend pytest and `scripts/smoke_phase5.py` sequentially so they do not contend for shared database state. Use Node 22 through `actions/setup-node`, project-local `frontend/node_modules`, and the committed lockfile for the frontend job.

## Verification

The workflow must appear as checks on a PR and both jobs must pass on GitHub's runner. Local verification includes the existing backend suite, frontend tests and build, and the real smoke script from merged main. A failure in migration setup or either test path blocks the corresponding CI job visibly.
